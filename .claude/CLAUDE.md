# 민초의, 민초를 위한, 민초에 의한

전시회 출품용 싱글플레이 미니게임 모음. 1인 개발, 기간 약 4개월.
자세한 기획: `docs/기획서.md` (규칙이 애매하면 먼저 읽는다. 기획이 바뀌면 이 파일도 함께 갱신)

## 기술 규칙

- 엔진: Godot 4 일반(Standard) 버전, 언어: GDScript만 사용 (C# 사용 안 함)
- **Godot 4 문법만 사용.** Godot 3 문법 금지
  - `onready var` → `@onready var`, `export var` → `@export var`
  - `yield(...)` → `await ...`
  - `connect("signal", self, "method")` → `signal.connect(method)`
  - `KinematicBody` → `CharacterBody3D`, `Spatial` → `Node3D`
- 가능한 한 정적 타입을 쓴다 (`var count: int = 0`, `func f(x: float) -> void:`)
- 시점: 실시간 3D + 고정 카메라. 3D 모델을 2D 평면 위에 배치하고 움직임도 평면으로 제한
- 화풍: 단색 로우폴리, 텍스처 없음, 옅은 그림자 (레퍼런스: Untitled Goose Game)
- 에셋: Kenney, Quaternius, KayKit (CC0). 재질은 단색으로 교체
- 해상도: 1920×1080 고정
- 스타일은 나중에 바꿔도 싸게 만든다: 색은 `common/style/palette.tres`, UI는 `common/style/theme.tres`에서만 가져오고 씬에 색을 직접 쓰지 않는다. 게임 로직은 모델·재질을 직접 건드리지 않고 시그널로 알리며, 겉모습은 서브씬으로 분리한다
- 미니게임 id와 폴더명은 영문 고정 id를 쓴다. 표시 이름은 `main/minigame_list.tres`에만 둔다
- 입력: PC + 마우스만 지원
- 씬 파일(.tscn)은 구조가 단순할 때만 직접 수정한다. 복잡하면 노드 구조를 제안하고 사람이 편집기에서 만든다

## 폴더 규칙

```
프로젝트 폴더/ (res://)
  project.godot
  .claude/       # Claude Code 설정과 이 파일(CLAUDE.md)
  docs/          # 기획서 등 문서. .gdignore가 있어 Godot이 무시함
  common/        # 공통: 결과 화면, 등급 계산, 득표 상태, 튜토리얼 틀, 리더보드
  minigames/
    <수법이름>/   # 미니게임마다 폴더 하나 (씬, 스크립트, 전용 에셋)
  assets/        # 여러 미니게임이 같이 쓰는 모델, 사운드, 폰트
  main/          # 타이틀, 미니게임 선택 화면, 최종 개표
```

docs/와 .claude/ 안에는 게임 리소스를 두지 않는다.

미니게임끼리 서로 직접 참조하지 않는다. 공유가 필요하면 common/에 둔다.

## 게임 개요

- 투표 주제: 민초 vs 반민초 (결과가 아무 의미 없는 선호 싸움). 민초 = 초록, 반민초 = 갈색
- 플레이어: 소수파 민초단. 시작 득표는 민초 열세 (예시: 30% 대 70%)
- 무대: 가상의 마을. 실제 정당·인물·선거를 연상시키는 이름, 색, 상징은 쓰지 않는다
- 게임 안에서 전자투표·블록체인은 언급하지 않는다
- 톤: "고작 이걸로 이렇게까지?"의 웃음. 실패 장면도 웃기게

## 흐름

1. 타이틀
2. 미니게임 선택 화면 (7개 전부 해야 하며, 순서는 자유)
3. 미니게임마다 짧은 튜토리얼(마리오 파티식) → 플레이 (30초~1분)
4. 결과: 등급 + 득표 변화 → 선택 화면으로 복귀
5. 7개를 모두 마치면 최종 개표: 종합 결과, 칭호, 리더보드

## 등급과 점수

- 등급: 완전범죄 / 미션성공 / 적발
- 등급을 득표 변화로 바꿔 최종 개표에 반영한다 (원점수를 합치지 않음)
- 전부 미션성공 이상이면 민초가 이기도록 맞추고, 전부 완전범죄면 추가 이벤트
- 구체 수치는 플레이 테스트로 정한다. 코드에서는 한 곳(설정 리소스 등)에서 조정 가능하게 만든다
- 리더보드: 종합점수(등급 점수 합) + 미니게임별 등급 + 칭호

## 미니게임 (이름은 구상용, 최종 이름은 미정)

| # | 구상명 | 핵심 |
|---|---|---|
| 1 | 임신한 투표함 | 참관인이 오기 전 접힌 모양이 제각각인 표를 마우스로 끌어다 중력 있는 투표함에 떨어뜨려 쌓고(수박게임처럼 쌓되 합쳐지지 않음) 뚜껑 닫기. 목표 장수를 넣어야 성공, 선을 넘게 쌓으면 뚜껑이 안 닫혀 실패. 물리 퍼즐 + 시간 압박. 코드: `minigames/ballot_box/` |
| 2 | 피아노표 | 일정한 박자로 넘어오는 표 중 반민초 표만 박자 맞춰 찍기. 감시자 등장은 한 박자 전 소리+화면 예고, 그 박자엔 찍으면 안 됨 |
| 4 | 샌드위치표 | 5장 묶음이 하나씩 나옴. 쌓을지(히트) 닫을지(스탠드). 닫은 다발의 맨 위·맨 아래 묶음이 민초면 전부 민초로 집계. 100장 초과 시 버스트 |
| 5 | 올빼미표 | 격자 맵 암기. 불이 여러 번 점멸(깜빡임으로 예고). 켜지면 외우고, 꺼진 시간에만 이동. 켜진 순간 감시자 시야(바닥 표시)에 있으면 실패. 감시자 패턴은 일정. 모든 투표함 처리 시 성공 |
| 6 | 사라지는 잉크 | 다리미를 대는 시간 조절(맥주 따르기형). 한 번 떼면 끝. 김이 나면 기표가 지워진 것(모든 종이 동일), 테두리가 누레지다 타면 실패. 타는 속도는 종이마다 다름 |
| 8 | 다그닥-바와스 | (추천안, 미확정) 칠판의 반별 숫자 중 정해진 칸 수만 고쳐서 참관인 검산(반별 합, 전체 합, 투표자 수) 통과시키기 |
| 9 | 미친 쥐 | 청기백기식. 오는 주민을 왼쪽(투표소)·오른쪽(저수지)으로 보내기. 헷갈리게 입은 주민이 섞임 (판별 단서 미정) |

## 작업 방식

- 한 번에 미니게임 하나씩. 먼저 하나와 공통 결과 화면을 완성해 구조를 검증한다
- 새 기능을 만들기 전에 어떤 노드·스크립트를 만들지 짧게 설명하고 진행한다
- 작업 단위 하나가 끝나고 검증(에러 없음 확인)까지 마치면 묻지 않고 `commit` 스킬로 커밋한다. 검증 전이거나 에러가 남아 있으면 커밋하지 않는다. push는 하지 않는다
- 에러가 나면 Godot 출력의 메시지를 근거로 원인을 찾는다. 추측으로 고치지 않는다
