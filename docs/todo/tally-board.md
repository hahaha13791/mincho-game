# tally-board (8번, 다그닥-바와스, id `tally_board`)

## 현재 상태: 임시안 (재미없다고 판정, 재설계 전까지 이대로 둠)

규칙: 칠판에 4개 반의 민초/반민초 숫자(플레이마다 랜덤), 도장 찍힌 반 합계, 맨 아랫줄 민초 합·반민초 합, 투표자 수. `−`/`+`로 최대 6칸까지 고치고, 한 칸의 변경 폭은 원래 값의 ±20%. 제출하거나 60초가 지나면 참관인이 검산(반별 합, 전체 합, 투표자 수). 하나라도 틀리면 적발. 이론상 최대 이득의 90% 이상이면 완전범죄, 50% 이상이면 미션성공, 미달이면 적발. 수치는 `tally_config.tres`. 2D HUD만 사용(3D 없음).

- [~] 규칙 로직과 플레이 씬 (`tally_rules.gd`, `tally_board.tscn`/`.gd`)
  - 테스트(자동): `-s res://minigames/tally_board/test_rules.gd` → TEST OK (통과)
  - 테스트(자동): 최적 해법을 입력하는 시뮬레이션에서 6칸 수정, 이득 +10, 완전범죄 확인 (통과)
  - 테스트(수동): 실제 화면에서 배치와 버튼 조작 확인 (미실시)

재미없는 이유: 정답이 하나(허용 폭이 큰 두 반을 골라 네 칸, 맨 아랫줄 두 칸)라 알면 계산만 남음. 참관인이 눈앞에 없어 긴장감이 없음. 웃음을 줄 연출이 없음.

## 재설계 후보

- [ ] **1안 시선 피하기 (추천)**: 참관인이 칠판을 반별로 한 줄씩 훑으며 지나감. 참관인이 서 있는 줄을 고치면 즉시 적발. 한 번 검산받은 줄은 다시 안 봄. 아직 안 온 줄은 합이 맞게 고쳐야 하고, 지나간 줄은 자유롭게 고칠 수 있음. 마지막에 맨 아랫줄과 투표자 수를 검산. 어느 줄을 언제 고칠지가 선택이 됨. 수법의 원래 모습(검산하는 눈 피하기)과 맞음
- [ ] **2안 한 표씩 옮기기**: 숫자 대신 표 토큰을 끌어 반민초 칸에서 민초 칸으로 옮김. 옮길 때마다 합이 어긋나 다른 줄에서 맞춰야 함. 참관인이 불시에 한 줄을 골라 검산. 조작이 직접적이라 계산 부담이 줄어듦
- [ ] **3안 접기**: 8번을 빼고 6개로 진행. 기획서의 "마감 직전에 덜 된 미니게임을 빼도 전체가 무너지지 않는다" 원칙 활용

다른 미니게임의 일정 때문에 재설계는 나중에 함. 확정하면 `docs/기획서.md`의 8번 행도 같이 갱신.
